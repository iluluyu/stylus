# 中文清晰写作参考（借鉴 ASD-STE100 原则）

本文件将 **ASD-STE100（简化技术英语）** 的核心认知原则迁移到简体中文，重点解决 AI Agent 在中文技术解释、问题排查、方案汇报与操作说明中常见的**逻辑跳跃、句式臃肿、因果缠绕与 AI 腔**问题。

ASD-STE100 是面向英文的受控语言标准，没有官方中文词典。中文部分不追求机械的词表限制，而是落地其背后的**低认知负荷原则**：让叙述顺序贴合读者思维，让每句话只承担清楚的一件事。

---

## 一、叙述骨架：让 Agent 的说明更有条理

好懂的中文技术叙述，首先取决于**信息顺序**，其次才是用词。

1. **先给心智模型，再进细节**
   - 解释概念、架构或代码时，先用 1–2 句话说清“它解决什么问题、核心怎么工作”，再拆模块或边界情况。
   - 不要一上来就罗列参数、文件名或边缘分支。
2. **由已知推未知，句子前后咬合**
   - 每句话优先以读者已经知道的对象开头，把新结论、新动作放在句末。
   - 按固定主线推进：**现象 → 原因 → 动作 → 结果**，或 **总览 → 步骤 → 注意事项**，不要来回跳叙。
3. **把因果拆开，不揉成一团**
   - 避免“通过……实现了……从而……”把手段、机制和结果压进一个长句。
   - 先说做了什么，再说带来什么变化。
4. **明确区分事实、推断与边界**
   - 代码或日志里直接看到的写为事实；尚未完全证实的标明“可能是 / 推测”；没检查到的范围直接说明，不把猜测说成定论。
5. **用结构承载并列，但不过度分段**
   - 3 项以上的并列要点、对比维度或操作步骤，优先用短列表或小表格。
   - 两三句话就能讲清的因果链，用自然段写完即可，不要硬拆成多层标题。

## 二、STE 原则 → 中文落地对照表

| 维度 | STE 对应理念 | 中文落地规则 | 解决的常见病 |
| --- | --- | --- | --- |
| **词汇选择** | Vocabulary (Rules 1.1–1.4) | 用常用动词和具体名词；去掉“进行/加以/实施 + 名词”包装。 | 官腔重、动词无力、水词多。 |
| **术语一致** | Consistent names (Rule 1.11) | 同一概念全篇固定一个名称，不为“文采”轮换近义词。 | 读者分不清两个词是不是同一对象。 |
| **拆解长定语** | Multi-word nouns (Rules 2.1–2.2) | 超过两层的“的”字长定语拆成两句：先说主体，再补充属性或用途。 | 读到句尾忘了主语是谁。 |
| **主语与语态** | Voice & Verbs (Rules 3.1–3.6) | 谁做动作谁当主语，优先主动语态；少用无主句和欧化“被”字句。 | 看不出动作执行者，逻辑发虚。 |
| **断句与句长** | Explanations (Rules 6.1–6.6) | 说明句尽量 ≤ 35 字（不宜超过 45 字），指令句 ≤ 25 字；杜绝“一逗到底”。 | 一整段只有一个句号，喘不过气。 |
| **操作指令** | Instructions (Rules 5.1–5.3) | 一句只写一个动作（同时动作除外）；直接用祈使句，少用“应当/务必”。 | 读者按步骤执行时容易漏步。 |
| **条件前置** | Conditions (Rule 5.4) | 前提、触发条件或例外放在动作之前，用逗号隔开（“当……时，……”）。 | 先做了动作才看到限制条件。 |
| **安全与警示** | Safety text (Section 7) | 必须保留危险源、后果与必要动作；条件或后果前置，不可为精简删掉约束。 | 省略风险边界导致误操作。 |
| **去 AI 腔** | Remove stock phrases | 删掉空泛起手式、元话语、虚假递进和流行黑话，直接陈述事实。 | 机械感强、废话密度高。 |

## 三、中文高频冗余与改写清单

### 1. 消除“虚动词 + 名词化”

| 冗余写法 | 直接写法 |
| --- | --- |
| 对配置文件进行修改 | 修改配置文件 |
| 实现了对延迟的显著降低 | 显著降低了延迟 |
| 针对该问题开展深入分析 | 分析该问题 |
| 完成了对缓存数据的清理工作 | 清理了缓存数据 |
| 具备良好的可扩展性特征 | 易于扩展 |
| 在很大程度上取决于 | 主要取决于 |
| 旨在为用户提供更好的体验 | 为了改善用户体验 |

### 2. 清理元话语与 AI 腔套话

下列词语通常不提供新信息，直接删掉或换成具体事实：

- **空泛起手式**：`值得注意的是`、`需要指出的是`、`毋庸置疑`、`众所周知`、`总而言之`、`综上所述`
- **冗余预告语**：`下面我们将详细介绍……`、`接下来让我们来看一下……`（直接给出小标题或内容本身）
- **空洞修饰词**：`深度赋能`、`全面升级`、`全方位打造`、`核心抓手`、`底层逻辑`、`极大地`、`显著地`（改用具体数值、对比或机制）
- **虚假递进套路**：`这不仅是 A，更是 B`、`与其说是 A，不如说是 B`（仅在确实纠正误解时使用）

### 3. 消除“一逗到底”与多层“的”字定语

- **一逗到底**：当逗号后面的分句换了主语、或者开始讲下一步因果时，果断用句号断开。
- **长定语拆句**：把“用于 A 且支持 B 的 C 系统”改写成“C 是一个……系统。它用于 A，并支持 B。”

## 四、Agent 真实叙述场景改写示例

### 1. 原理与机制解释（心智模型先行 + 拆解长句）

- **改前**：值得注意的是，扩散模型是一种通过对训练数据逐步添加高斯噪声以将其破坏为纯噪声，然后再训练神经网络学习逆向去噪过程从而实现从随机噪声中生成高质量样本的生成式模型，其不仅训练过程更加稳定，而且生成效果也十分出色。
- **改后**：扩散模型通过“先加噪、再学会去噪”来生成样本。训练时，系统向真实数据逐步加入高斯噪声，直到数据变成纯噪声，再让神经网络学习每一步的逆向去噪。生成时，模型从随机噪声出发，反复去噪得到新样本。相比对抗训练，这套流程更稳定，生成质量也更高。

### 2. 问题排查与汇报（现象 → 根因 → 修复 → 边界）

- **改前**：经过排查我们发现，之所以接口会出现偶发超时的问题，主要是因为在高并发请求涌入的时候数据库连接池被打满了，并且由于缺少超时回收机制导致部分慢查询一直占着连接不释放，所以我们建议把连接池上限调大一点，同时加上查询超时时间。
- **改后**：
  - **现象**：高并发时接口偶发超时。
  - **根因**：部分慢查询没有设置超时时间，长期占用连接，导致数据库连接池耗尽。
  - **修复**：为查询添加 5 秒超时回收，并将连接池上限从 20 提高到 50。
  - **待确认**：该调整仅在当前读写比例下验证，大促峰值流量需另行压测。

### 3. 单句微调对照表

| 场景 | 改前 | 改后 | 改动要点 |
| --- | --- | --- | --- |
| **条件前置** | 在运行迁移脚本之前，用户必须确保已经对生产数据库进行了完整备份。 | 运行迁移脚本前，先完整备份生产数据库。 | 条件前置 + 主动祈使，删去“进行”。 |
| **一句一指令** | 拆下后盖并断开电池排线，然后取下主板。 | 拆下后盖。断开电池排线。取下主板。 | 每句一个动作，避免漏步。 |
| **去翻译腔** | 该错误通常是由一个未被正确初始化的指针所导致的。 | 未正确初始化的指针通常会引发这个错误。 | 明确主语，改为主动语态。 |
| **拆长定语** | 这是一个用于在高并发分布式环境下自动检测节点故障并触发主从切换的轻量级协调服务。 | 这是一个轻量级协调服务。它运行在高并发分布式环境中，负责自动检测节点故障并触发主从切换。 | 先交代主体，再补充环境与职责。 |
| **术语一致** | 先创建“工作区”，再把代码导入该“项目空间”，最后在“操作环境”中运行测试。 | 先创建工作区，再把代码导入该工作区，最后在工作区中运行测试。 | 同一概念一词到底。 |
| **安全警示** | 请勿在通电的情况下接触高压模块，否则可能会导致严重触电。 | 通电时切勿接触高压模块。接触带电部件会导致严重触电。 | 条件前置，完整保留危害与后果。 |

## 五、输出前 5 秒自检清单

在输出中文解释、分析或文档前，快速核对以下 5 项：

1. **主干可见吗？** 读者看前两句就能知道核心结论或整体机制吗？
2. **顺序顺畅吗？** 叙述是否按“现象 → 原因 → 动作 → 结果”推进，没有来回跳步？
3. **句子清爽吗？** 主语和动词是否直接？有没有“一逗到底”、超过两层的“的”字定语或“进行……处理”？
4. **废话删净了吗？** 有没有“值得注意的是”“总而言之”等不承载信息的套话？
5. **边界准确吗？** 数值、单位、前提条件、例外情况以及“事实 vs. 推断”的区分都保留完整了吗？

## 六、中英文混排与合规边界

1. **术语与英文原词**：
   - 中文已有通行译名时优先用中文；首次出现可括号附英文，如“注意力机制（attention）”，后文保持统一。
   - 行业内通行直接使用英文原词的术语（如 API、Token、Transformer、PR），无需强行翻译，全篇一致即可。
2. **风格与合规边界**：
   - 本参考用于提升中文叙述的清晰度与逻辑性，属于风格指南。
   - 不存在官方中文版 ASD-STE100；切勿对中文文本宣称“符合 ASD-STE100 标准”。
